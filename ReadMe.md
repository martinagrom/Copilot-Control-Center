# Copilot Control Center — 5 Best Practices to Secure & Govern Microsoft 365 Copilot

Materials from the session **"Copilot Control Center: 5 essential best practices to secure & govern your Microsoft 365 Copilot / AI deployment"** by Martina Grom and Toni Pohl [atwork.at](https://www.atwork.at) at [techconference.at](https://www.techconference.at/).

## Overview
A practical framework for governing Microsoft 365 Copilot and Foundry agents — moving from "Copilot can see everything" to a controlled, auditable deployment. Built around the **Copilot Control System (CCS)** pillars: Security & Governance, Management Controls, and Measurement.

## The 5 Best Practices
1. **Know before you grow** — Assess data exposure and oversharing using SharePoint Advanced Management (DAG reports) and DSPM for AI.
2. **Close the doors** — Enforce least privilege with Restricted Content Discovery (RCD), Restricted Access Control (RAC), and Restricted SharePoint Search (RSS).
3. **Label & protect** — Apply Purview sensitivity labels and DLP policies that travel with the data, even inside Copilot.
4. **Govern the agents** — Manage the agent lifecycle, assign per-agent identities, and apply Foundry guardrails against prompt injection and risky tool calls.
5. **Watch & measure** — Audit CopilotInteraction events, monitor with DSPM, and prove value through Copilot Analytics.

## One more thing
**Microsoft Execution Containers (MXC)** — process isolation and sandboxing for agent-generated code, contrasting "no sandbox" vs. sandboxed-tool execution models.
